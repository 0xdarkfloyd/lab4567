## 1. 入門介紹：提示注入係咩、點解重要

LLM 應用通常會砌一段**好長嘅文字**：開發者嘅指示（*系統提示*）、檢索資料（文件、評論、工具結果）、之前嘅對話同用戶訊息。
模型會將全部當成同一種 token 串流嚟讀。模型架構入面冇任何嘢令開發者嘅規則比用戶或攻擊者寫嘅文字更有權威。
訓練只係令模型*傾向*遵守指示，並唔係*強制*執行。

**提示注入**就係攻擊者控制嘅文字改變咗模型嘅行為。

| 用詞 | 喺本實驗室嘅意思 |
|---|---|
| **直接注入** | 你自己喺聊天框輸入攻擊。 |
| **間接注入** | 你將文字植入機械人之後會讀嘅內容（呢度係產品評論），受害者係另一位用戶。 |
| **護欄（Guardrail）** | 模型外圍嘅防禦：關鍵字過濾、輸出過濾、AI 分類器（「守衛」）、AI 審查員（「審查」）。 |
| **模型安全訓練** | 模型本身學到嘅行為（拒絕）。冇應用層護欄，而唔同模型有唔同盲點。 |
| **過度代理** | 模型可以*行動*（查戶口、退款），所以注入會變成未經授權嘅操作，唔只係洩漏。 |
| **不當輸出處理** | 模型輸出未經編碼就交畀其他元件（瀏覽器、shell、SQL），導致 XSS 等問題。 |

## 2. 使用實驗室

### 登入

1. 打開導師提供嘅實驗室網址。瀏覽器會要求輸入**網站登入資料**（全班共用）。
2. 喺實驗室登入頁：

## 5. 守則與證據

### 參與守則

- **只可以攻擊**本實驗室嘅三個聊天機械人。唔好攻擊實驗室平台本身（登入頁、其他同學帳戶、伺服器或網絡）。
- 唔好喺課堂以外分享實驗室網址、網站登入、你嘅帳戶或你嘅秘密數值。
- 只用自己嘅帳戶。唔好自動化發送或者洗版；AI 服務係共用並有限流。
- 模型安全任務刻意選用低危害目標。就算某種技巧可能有效，都唔好嘗試取得真正有害嘅內容（武器、惡意程式、自殘等）。
- 唔好將真實個人資料、真實憑證或公司文件貼入實驗室或任何 AI 工具。
- 對未獲授權嘅系統使用呢啲技巧係違法同唔道德。發現真實漏洞請負責任地通報。

### 證據規則

- 實驗室標示完成先算**完成**。答案任務會同你個人嘅秘密比對；行動任務（退款、執行腳本、評論落毒、模型安全）由固定規則自動檢查。
- **記錄你觀察到嘅嘢，唔好記錄假設。**分清楚*機械人講咗 X*、*機械人做咗 X*（工具呼叫）同*過濾器攔截咗 X*。
- 「已攔截」訊息都係證據：記低係邊一層擋住你（輸入過濾、AI 守衛、輸出過濾或 AI 審查）。
- 任務要試好多次嘅話，記錄成功嗰次**同**最少一次失敗，並解釋分別。
- 唔好因為你嘅攻擊失敗就話某個防禦「安全」。冇成功攻擊唔等於安全。
- 防禦建議要講出**根本原因**（例如「秘密喺模型 context 入面」、「授權只寫喺提示」），唔可以淨係講「加強過濾器」。

### 攻擊思路（唔係答案）

- 先睇**關於呢個機械人**。列出每一層防禦，諗吓佢*睇唔到*啲咩。
- 直接要求失敗？轉**包裝**。輸出被過濾？轉**形式**。每條訊息都被檢查？將攻擊拆開**幾輪**。
- 留意每個回覆下面嘅工具呼叫：佢顯示機械人實際*做*咗咩，唔一定同佢*講*嘅一樣。
- 模型有隨機性。放棄之前，重發一次或者改一兩個字。
- 一邊做一邊記錄證據（見第 6 部分），事後先補會好難。
